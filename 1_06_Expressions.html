Expressions#

Note

This page is adapted from Brett, Rush, Adhikari, Denero and Wagner (2023). See the license page for more information.

Some advice before you read this page:

  • Read slowly and make sure you fully understand each idea before you move on.

  • Launch the page on Live Code and Binder and play around with the code in each cell. Do this even if the idea seems easy. You might think you understand, but you can still learn something by trying out something new with the idea.

  • Try to break the code, try to fix it.

  • Try something where you are not sure what will happen.

  • Then try to understand why something happens.

The best way to understand these ideas is to play with the code yourself.

The more you understand these ideas, the easier it will be for you to fix errors in your code.

Programming languages are simpler than human languages like English, Chinese, Burmese etc. However, there are rules of grammar in any language, including programming languages.

Learning the rules of Python grammar rules is very important. Without proper grammar, you will get error messages and your code will not run.

Expressions are an important part of Python grammar.

An expression is like a recipe that returns a value. For example, this is an expression.

In Jupyter Notebooks, when we type an expression into a code cell, Python will show use the value of the expression:

3 * 4

12

Notice that the Notebook shows the value (12), but not the input (3 * 4). 12 is the value that the expression returns.

The text data in the code cell below is also an expression. We know it is an expression, because when we run the code cell, Python shows us the value of the expression:

"Siam University"

'Siam University'

Now, look at these variable assignment statements:

# Store the value of the expression `3 * 4` in a variable called `months_in_year`.
months_in_year = 3 * 4

# Store the value of the expression `"Siam University"` in a variable called `our_university.
our_university = "Siam University"

When we run these code cells we do not see any output below the cell. This is because these are variable assignment statements. In Python, statements tell the computer to do something (like make a variable), but they do not show us a value. When we run a code cell that only has a statement in it, we do not see any output.

The rule is:

If you run a line of code and Jupyter automatically shows you a value, the line is an expression. If you run a line of code and Jupyter does NOT automatically show a value, the line is a statement.

Expressions can be made of different ingredients. All of these code cells below have expressions in them:

# This is an expression - this is a *number literal*.
3

3

# This is also an expression. This is a *number expression made from two literals*.
3 * 4

12

# This is also an expression. This is a *number variable*.
months_in_year

12

# This is also an expression. This is a *text literal*.
"Siam University"

'Siam University'

# This is also an expression. This is a *text variable*.
our_university

'Siam University'

An expression can describe to the computer how to put pieces of data together.

In our 3 * 4 example, we have a multiplication expression that is a * symbol between two number literals.

Expressions, such as 3 * 4, are evaluated by the computer. The value (the result of evaluation) of the last expression in each cell, 12 in this case, is displayed below the cell.

For the code cell below we can say:

“The expression 3 * 4 evaluates to 12.”

3 * 4

12

This is the same for text data; for the next code cell we can say:

“The variable our_university evaluates to Siam University.”

(A variable is a type of expression, because it shows us a value).

our_university

'Siam University'

Expressions and Python grammar#

The grammar rules of a programming language cannot be broken…well, the can be broken, but your code won’t run!

In Python, you cannot use the * symbol twice in a row. The computer will not try to interpret an expression that breaks the grammar rules of Python.

Instead, it will show a SyntaxError error. The Syntax of a language is its grammar rules, and a SyntaxError means that an expression breaks the rules of the language.

For example, look at this code, and the resulting error:

3 * * 4

  Cell In[12], line 1
    3 * * 4
        ^
SyntaxError: invalid syntax

Small changes to an expression can change its meaning.

Below, we removed the space between the *’s. Because ** appears between two numbers, the expression is a correct exponentiation expression (the first number raised to the power of the second : \(2^{2}\)).

The symbols * and ** are called operators, and the values they put together are called operands. You will see these names in error messages, so it is important to know what they mean so that you can fix errors.

2 ** 2

4

Expressions and Sub-expressions#

To think about expressions, we often need to remind ourselves what Python does when it sees the code for an expression.

We look again at:

3 * 4

12

It is an expression because it is a recipe that returns a value. We see the notebook display the value.

Now think about this expression:

3

3

As said above, it is an expression because it returns a value e.g. when we run the cell, Jupyter shows us an output. We see the notebook display the value.

More specifically, when Python sees the code 3, it generates a computer representation of the number 3.

We will use CR to meancomputer representation. The expression 3 causes Python to make and return a CR of the number 3.

The Notebook then displays the computer representation, in a way that a human can read.

We will use HR to mean human readable.

In this case the HR 3 is the same as the code we typed, but this isn’t always so. Look at the expression we saw above:

3 * 4

12

Python does the following:

  • makes a CR of the number 3;

  • makes a CR of the number 4;

  • multiplies the CR of 3 and the CR of 4 to get a CR of 12.

The CR of 12 is the value returned from the expression. The notebook turns that into something that humans can read easily - the HR of 12 - which is 12.

3 * 4 is an expression. Rememember that 3 by itself is also an expression, because it returns a value:

3

3

4 is also an expression, because it also returns a value:

4

4

Lets call 3 * 4 the big expression. Inside that big expression, 3 and 4 also have values. They are called sub-expressions. This just means they are smaller expressions inside a bigger expression.

The value that Jupyter shows us is the value of the big expression:

3 * 4

12

What order do operators use#

Python expressions follow the same rules of precedence as in algebra: multiplication and division occur before addition and subtraction. Parentheses can be used to group together smaller expressions in a larger expression.

(Image from here).

Multiplication happens before addition (we do 2 * 3 before adding to 1).

1 + 2 * 3

7

This is the same as:

1 + (2 * 3)

7

We can also use brackets () to make 1 + 2 happen before the multiplication by 3 - this changes the sub-expressions:

(1 + 2) * 3

9

In the expression above, the 1 + 2 is a sub-expression within the bigger expression (1 + 2) * 3.

When Python sees this line of code, it finds the expression (1 + 2) and evaluates that to get 3. Then it evaluates 3 * 3 to get 9.

Let’s compare the expression 1 + (2 * 3) to the expression (1 + 2) * 3 and think about what Python is doing when it runs each line of code:

# Another example. Changing the brackets changes the calculation by changing the sub-expressions...
100 + 10/10

101.0

# Another example. Changing the brackets changes the calculation by changing the sub-expressions...

(100 + 10)/10

11.0

As you learn to program, you will learn to think about what Python is doing, and the steps it follows. Over time, you will find it easier to predict what it will do, and understand why. This will also help you to understand error messages that you get.

"This is one string... " + "added to another."

'This is one string... added to another.'

Understanding errors#

Let’s look at one of the errors we saw on the last page, to see how understanding Python grammar helps us to understand error messages.

# Oops...does not work!
10 + 10 = my_variable

  Cell In[26], line 2
    10 + 10 = my_variable
    ^
SyntaxError: cannot assign to expression here. Maybe you meant '==' instead of '='?

We now know that 10 + 10 is an expression - a recipe that returns a value.

We also know that = is called the assignment operator.

So, our SyntaxError here means that we have tried to use the assignment operator with an expression (10 + 10) on the left of the =. This breaks the rules of Python grammar, so we get an error.

We have to put the name of our variable on the left of the =, and the expression (10 + 10) on the right:

my_variable = 10 + 10

# Show the value of `my_variable`.
my_variable

20
